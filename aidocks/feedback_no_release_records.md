**Don't write down each release the dev makes.** No note in `aidocks/`, and no line in `README.md`, says which versions went out, when, with how many changelog entries, or with which zip, tag or "Release" commit.

**Why:** A standing rule the dev carries across their projects: "People do not need to see that I made x release."

**How to apply:**
- When the dev says they released, check GitHub if asked, and answer in chat. Don't offer to record it.
- The rules about releases stay: the entry limits ([[feedback_changelog]]) and how the releaser works. What stays out is the per-release history.
- Version numbers used only as examples of the format, such as `26.10.02-1`, are fine.
- The changelog's own version headings are the releaser's work and stay as they are.
