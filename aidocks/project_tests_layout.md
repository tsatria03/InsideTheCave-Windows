The `tests/` folder was set up with two empty folders before the first session:

- **`tests/case/`**: the automated tests. One plain script per area, named for what it covers (`paths.py`, `runloop.py`, `gameplay.py`), with no `test_` prefix on the file; the functions inside start with `test_`. Each finds the repository by going two folders up from itself, then imports `_scratch_save` ([[project_safe_test_run]]), and ends with `_scratch_save.run(globals())`. Since 2026-10-02: `paths`, `runloop`, `save`, `speech`, `keymap`, `sound`, `language` (phase 1), `scene` (phase 2), `gameplay` and `app` (phase 3), `screens` (phase 4).
- **`tests/interact/`**: tools the dev plays by ear, each on its own save. They are not tests, and Claude never runs them, since they make sound and speak ([[feedback_interactive_tests]]). Since 2026-10-02:
  - `platform_check.py`: phase 1 by ear, before there is a game; all its checks passed by ear on 2026-10-02 (the dev). A menu in its own window (Up, Down, Enter or the number; Escape stops a check; Alt+F4 quits at any moment): the roar and the bats placed left, centre and right; the bats at 1.0 and 0.7 (the roar at 3.0 and 1.0 until the dev's cap at 1.0); stereo against mono; every sound 2.32 plays; the tutorial line in the SAPI voice followed by the key hints; the master volume; the installed voices. Its own save in `%APPDATA%\InsideTheCave\platform_check`.
  - `scene_check.py`: phase 2 by ear; all its checks passed by ear on 2026-10-02 (the dev), built on `platform_check.py`'s window and keys (it imports them): short previews built from the SpriteKit stand-in, a monster, bats or a jingling coin down each lane with the roar at the sensor and "now" when it would reach you, you in each lane, eight monsters in a row. Its own save in `%APPDATA%\InsideTheCave\scene_check`.
  - `stage_chooser.py`: phase 3 by ear, the real game started from a chosen point (the beginning, slot 75 before the water, 155 before the ice, 400 at the top speed; since the fourth release on Easy, Medium or Hard, chosen with Left and Right, its tops 3.0, 2.0 and 1.0), with the tutorial and debug mode on or off; a menu in `platform_check.py`'s window, then the game in its own. Its own save in `%APPDATA%\InsideTheCave\stage_chooser`.
  - `screens_check.py` (since the fourth release also a fifth start, the tutorial with its welcome): phase 4 by ear, the same kind of menu, then the real program: from the earphone warning, the result screen at once with a made-up score of 150 (third place) or 5 (too low), or a game for the pause menu and a real game over. Each start writes a made-up top five (Ana 300, Ben 200, Cleo 100, Dev 50, Eli 10). Its own save in `%APPDATA%\InsideTheCave\screens_check`.
  - `torch_check.py` (added for the third release, at the dev's request: "Can you add a quick torch test? Make it interactive."): the real game with the torch nearly burnt out (falloff 4.95: "Torch low", then the burning-out sound about 3 s in), about to dim (2.99: "Torch low" about 3 s in, burning out 29 slots later), or full, for throwing. Nothing else comes down the cave: no torch pickups (the dev: "Only spawn one torch.") and no monsters, bats or coins (the dev: "Please do not spawn monsters, bats, and coins."); each is an empty slot, so the slots and the torch keep their pace. A throw sends one torch pickup down a lane the game picks (the dev: "If you throw a torch in the test, then 1 should get spawned in any lane."), said as "A torch is coming." Its own save in `%APPDATA%\InsideTheCave\torch_check`.
  - `coin_check.py` (the dev, for the third release: "Please make a coin check script, interactive."): the real game with only coins coming down the cave, as the game sends them, or with more, a coin also where each monster, bat and torch would have been. No monsters, bats or torches, and your torch does not burn down. Its own save in `%APPDATA%\InsideTheCave\coin_check`.
  - `tutorial_check.py` (the dev, for the fourth release: "Can you make a deticated tutorial  tester? In interact? I want to make sure that one works."): the real Tutorial, as chosen from the main menu with its welcome, as after Replay without it, with only coins and torches, or with only monsters and bats and the torch lit again a second after each throw, for the throw lines; D for debug mode. Caught goes to "You were caught." as in the game. Its own save in `%APPDATA%\InsideTheCave\tutorial_check`.
  - `bat_check.py` (the dev, for the third release, after finding thrown torches did not move the bats: "I also want an interactive bat test if possible."): the real game with every obstacle bats, and no coins or torches on the path; either bats that can kill you, or debug mode, where one that reaches you says "Hit". The game's own dodge, the bats' sound going with the bat, then the screen reader says which lane it went to, to check the sound by. Your torch never burns down, and is lit again, with the pickup sound, about a second after each throw. Its own save in `%APPDATA%\InsideTheCave\bat_check`.
  - `speed_check.py` (the dev, for the third release, "developer tool only"): the full game with `speedMonster` held where the dev sets it, as the E key's count since the fourth release: Equals faster and Minus slower, one speed-up at a time, "Speed, 0." to "Speed, 40." (the dev: "What if minus and equals increased and decreased the speed, like speed 0, speed 1."; first it was Minus faster by 0.1 of speedMonster), held to the game's own limits, from 5.0 to 1.0 (`GameScene.START_SPEED`, `TOP_SPEED`; the dev: "the speed checker script should cap to those speeds as well.", where it first ran from 0.1 to 10.0), never stepping by itself (the game's speed-up every 20 slots is put back after each slot); starts at 5.0, debug mode a choice, the speed kept over Restart and Replay. Its own save in `%APPDATA%\InsideTheCave\speed_check`.

**Why:** The dev's layout for their ports.

**How to apply:** Put a new automated test in `tests/case/`, and match a change to the test file that covers it ([[feedback_dont_run_or_build]]). Whenever something can be heard, add a check to a tool in `tests/interact/` too ([[feedback_interactive_tests]]).
